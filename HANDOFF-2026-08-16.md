That has never once been true, and v13 is the first build where it can be. If
she is stable, the tones are finally worth judging — same identity, different
delivery. Every previous audition was strangers, so nothing you have heard so

## What was wrong, and what fixed it

Five separate faults, found in this order. They overlapped, which is why it
took a day: several of them produce the same visible symptom.

**1. Unintelligible speech — `optimize=True`.**
VoxCPM2 ran under CUDA Graphs, which its FAQ says are incompatible with
multi-threading, and RunPod calls the handler on a new thread per job. The
documented fix is `optimize=False`. We had reached for a global
`torch._dynamo.config.disable` instead, which stopped the crash but left the
model on a code path nobody tests. This is why its own quickstart sounded
broken: it was not the model, it was the thread calling it.

**2. "I can't reach my brain" — two faults wearing one message.**
The Cloudflare binding was named `CLAUDE_API_KEY` while the Worker reads
`env.ANTHROPIC_API_KEY`. A missing binding is `undefined`, not an error, so it
sent an empty key and Anthropic replied `invalid x-api-key` — a message about
the key's *value* that was really about its *name*. A good key got rotated for
nothing.

Fixing that only moved the failure to `400 model: Field required`. All three
API call sites were missing required fields: chat sent neither `model` nor
`max_tokens`, prayers and meditation questions sent `model` only. None of the
AI features could ever have worked.

Both now fixed; the model id is a single constant, `LULO_MODEL`.

**3. Silence with healthy logs — refused playback, swallowed.**
`audio.play()` rejects when the browser refuses, and that rejection was wired
to the "finished speaking" path. A refusal was indistinguishable from a
completed sentence: no sound, no error, nothing in any log. iOS grants playback
to an *element* the user already started and the grant does not survive a long
wait — and Lulo's audio arrives after a round trip that can be a cold start
long. Now: one element, primed with a silent clip on first touch and reused;
and a refused play falls through to the Web Speech voice so failure is at least
audible.

**4. No stable voice — `seed supported: False`.**
This build of `voxcpm` has no `seed` parameter and has silently ignored it
since v10, so every call sampled a new speaker. test_v10 sounded right by
luck. The seven tones that came back as seven different people were seven
strangers, not range. Fixed by seeding torch's global generator, which the
library's sampling draws from either way. **v13 is the first build carrying
this.**

**5. The Worker dropped `tone`.**
`/tts` destructured `text` alone, so `tone`, `voice` and `seed` never reached
RunPod. Already deployed by you. It also removes a 5s floor on every line she
spoke (the poll loop slept before its first check).

## Also fixed and live

- **Mic cut you off mid-sentence.** It sent on the first finalised result, and
  the recogniser finalises at every pause. Now a pause restarts a silence
  countdown, and a session ending (Safari caps them during long speech) opens a
  fresh one carrying the text across. Up to 90s per turn.
- **Text mode unreadable on pale themes.** Input was 1.33:1 contrast, now
  16.55:1. Bubbles and timestamps too. Measured, not eyeballed.
- **Lulo watermark in the corner.** Her `float` animation replaced the
  `translate(-50%,-50%)` that centred her, dropping her 150px right and down.
  She has her own `floatCentred` keyframes now.
- **Android page sliding + mic overlapping the deck.**
- **Theme 3 has the original green Lulo.**

## Open, not urgent

- **Firebase: `Missing or insufficient permissions`.** Firestore rules reject
  writes, so cross-device sync via Lulo Code is silently broken. Untouched.
- **Anthropic balance was $1.00.** Top it up or she will go quiet again, and
  the failure will look different from anything above.
- **The image is 39GB**, ~30GB of which is the `-devel` base carrying the whole
  CUDA toolkit for compiling — which we no longer do, since `optimize=False`.
  A runtime base could cut it by more than half. Worth testing, not urgent.
- **The tone wordings are a first guess.** If `sad` and `happy` sound like
  different women once seeding works, the fix is to pull that tone's wording
  back toward the identity clause.
- **`swipe-to-text` responds to tap as well as swipe** — deliberate, tap is the
  accessible one. Label could read "Tap or swipe to text".

## Standing notes

- Active Workers **0** when not testing. Max Workers **1** or nothing can run.
- Service worker is **network-first** for the shell, so a deploy shows up on
  the next launch. No SW bump needed for the app to update; bump only to clear
  the offline copy. Currently `emq-v37`.
- A cached `styles.css` hid a working CSS fix during testing. If a change seems
  not to have landed, suspect the cache before the code.
- The Worker lives at `worker/index.js` now. Cloudflare is the source of truth;
  that file is a mirror, so keep them in step.
